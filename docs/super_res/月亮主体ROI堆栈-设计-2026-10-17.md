# 月亮（暗背景亮小主体）ROI 堆栈 — 设计 — 2026-10-17

> 触发：2026-10-17 晚 9 张月亮 NEF（Z6 + 200mm f/8 1/100s ISO100）跑通用超分管线，
> 输出 11330x7446 的母版里有效内容只有 316px 的月盘，预览 JPG 里月面成白饼。
> 本文记录实测数据、根因、新链路的做法与验证。代码：`sr_moon.py` +
> `sr_process.process_subject_roi()`。

0.3 灰、月面 80% 像素贴顶；新 JPG 天空 0.02、月面中位 0.49、贴顶 0%。

## 二、通用管线为什么在这类画面上失效

1. **对齐/光度/噪声权重都在整帧上估**：99% 的黑天空没有梯度，相位相关峰、ECC
   单应、增益偏置、模糊 RMS 全被黑背景与天空噪声主导；
2. **画布按全帧位移取交集**：为 1 个 316px 的目标产出 11330x7446（86MP）母版，
   99.6% 是黑；
3. **去鬼影的中位数锚定按"内容会动"设计**：月亮是刚体，这里只有坏处；
4. **预览按全帧分位拉伸**：黑主导画面白点落在天空上 → 主体拉顶；
5. **RL 去卷积 σ 固定 1.0px**：在 2x 图上等于 0.5 原生像素，而实测 PSF σ 1.2+
   原生像素——几乎没锐化；
6. **纯平移配准**：分组间的 0.3° 滚转在 316px 盘缘上是 0.8px 错位，直接抹掉
   亚像素增益。

## 三、新链路

```
半尺寸解码逐帧检测（暗背景 + 紧凑亮小目标）
  → 主体直径/中心/面积占比/对比度/圆度判定（不满足则回退通用管线）
  → 全尺寸解码，逐帧以主体中心裁 ROI（1.35×半径余量）
  → 逐帧盘缘 10-90% 宽度（锐度代理）→ 选最锐做参考帧
  → 配准：相位相关粗解 → 梯度加权高斯-牛顿平移精修（~0.01px）
          → ECC 欧氏补旋转（验收制：残差须 ≤0.98× 平移解且 |θ|≤2°）
  → 光度归一：增益=盘内中位比、偏置=天空比（都在主体域内估）
  → lucky 选帧：边缘宽度 ≤ 最锐×1.25 的帧参与，权重 (e_min/e)^4
  → scale 倍网格逐帧 remap 融合（双三次）
  → PSF 实测（融合图盘缘 ESF）→ RL 去卷积（σ=实测，24 iter）
  → 主体中位定标渲染（黑点=0，中位→0.50，0.8 以上软肩）
  → Linear DNG 母版（ROI 尺寸）+ JPG
```

检测门限（`sr_moon.detect_bright_subject`）：面积占比 ≤6%、与背景对比度 ≥15×、
圆度 ≥0.55（等面积/外接圆）、且全帧 P90 < 峰值×0.10（暗主导）。任一条不满足就
不当成"小主体"——普通风景/夜景城市不会误判（单测覆盖）。

## 四、关键取舍

- **为什么按主体中位曝光而不是按高光定白点**：月面的动态范围很窄（中位/峰值≈2），
  按高光定标会让中位落到 0.73 以上的"洗白"区；按中位定标则月海/高地/亮纹的层次
  都在 0.3–0.8，亮纹用软肩压住不硬裁。星空/深空同理（亮内容中位定标）。
- **为什么 lucky 选帧**：不同帧的 seeing 不同，糊帧不是"多一帧平均"，而是把整堆
  往糊的方向拉。本组 9064/9071/9076/9082 明显比 9086–9096 糊（3.4–3.7px vs
  2.9–3.1px），权重压到 0.5–0.8。
- **为什么不追求"比最锐单帧更锐"**：9 帧平移堆栈的物理上限是"PSF 不变、采样更密、
  噪声更低"。盘缘宽度不会因为堆栈而变窄（PSF 是光学/大气给的），能拿到的是
  噪声 1/3、无拜耳/像素栅格混叠、以及**有本钱做更强去卷积**。

## 六、通用管线的顺带修复

`render_srgb_preview` 的拉伸分支加"黑主导"判别：全帧中位 < P99.5×0.02 时
（月亮/星空/深空），黑点保持 0、按亮内容中位曝光、0.9 以上软肩。普通亮画面
（组01/02/03 那类）走原 0.5/99.5 全帧拉伸，观感不变（有回归单测）。

## 七、已知边界

- 只做纯平移 + 小角度旋转（≤2°）；大角度旋转/缩放不适用（会退回平移解）；
- 主体越界（离画面边缘 < 1.35×半径）直接回退通用管线；
- 9 帧、seeing 限制下无法超过单帧的光学分辨率；要提高得靠更多帧（lucky imaging
  取最锐 5%）+ 更大口径，不是算法能补的；
- 帧数上限：解码上限 `SUBJECT_MAX_DECODE=40`（超长组按半尺寸锐度预筛）。

## 八、为什么这组没有"分辨率增益"（定量，回答"亚像素不是能提升分辨率吗"）

亚像素多帧 SR 本质是**解混叠（de-aliasing）**，不是**去模糊（deblurring）**。
传感器把连续图像 I 按 1px 网格采样：f(n) = (I ⊛ box)(n·p)。当 I 在 1/(2p) 以上
有能量时采样才混叠；N 帧亚像素偏移给出 N 倍采样，就能把混叠带解回来。两个前提：

1. **I 在奈奎斯特以上确实有能量**（否则 F 帧之间只差插值，没有新信息）；
2. 偏移要准（否则是叠加模糊而不是叠加采样）。本组 2 已满足（0.01px 配准、
   0.1–0.9 的真实亚像素多样性），1 不满足。

实测（`devtests/moon_sr_limit.py`，直接在本组 2x 母版上量）：

| 项 | 数值 |
|---|---|
| 盘缘 10-90% | 2.83px（原生） |
| PSF σ（含衍射/像素孔径反折） | **1.10px**，FWHM 2.6px |
| 其中 seeing / 衍射(f8@200mm) / 像素孔径 | ≈1.01px / 0.32px / 0.29px（平方和） |
| PSF MTF @0.2 cyc/px | 0.382 |
| PSF MTF @0.3 cyc/px | 0.115 |
| PSF MTF @0.4 cyc/px | 0.021 |
| **PSF MTF @0.5 cyc/px（像素奈奎斯特）** | **0.0024** |
| 母版盘内 PSD @0.30 cyc/px（相对噪声底） | 仅 8.7dB |

结论：**单帧在奈奎斯特处只剩 0.24% 的对比度**——像素网格没有截掉任何东西，
也就不存在可解的混叠。堆栈能做的只有：噪声 1/3、去掉拜耳/像素栅格采样痕迹、
从而允许更强的去卷积（这才是 9 帧真正换来的东西，已做：σ=2.27px@2x、24 iter）。

反过来说，什么时候亚像素堆栈真的能翻倍分辨率：PSF 窄于像素时（σ ≲ 0.4px，
例如大孔径短焦 + 好视宁度），此时 0.5–1.0 cyc/px 有真实内容，混叠显著。
这时 9 帧就能看出明显差别——本组不是那个 regime。

要提高本组的分辨率，只有三条路（都不是软件）：
1. **lucky imaging**：拍几百帧（Z6 14fps 连拍或 4K60p），只叠最锐的 1–10%
   ——视宁度是随机过程，9 帧里没有"好瞬间"可选（本组 2.93–3.56px 都差不多）；
2. **更大口径**：200mm f/8 的有效口径只有 25mm，衍射 σ 0.32px；
   换 400mm f/5.6（71mm）衍射降到 ~0.16px，同时像面放大一倍；
3. **等月面更高**：19:46 的高度角低、大气质量大，seeing 和色散都吃亏
   （盘缘的蓝/黄色散边就是证据）。

## 九、超分的三条技术路线，与 JSR 为什么看起来更好

### 9.1 三条路线（决定了能拿到什么）

| 路线 | 原理 | 能拿到 | 拿不到 |
|---|---|---|---|
| **多帧采样 SR**（本管线） | N 帧亚像素偏移 → 解混叠，把 1px 网格换成 2x 网格 | 采样更密、噪声 1/N、无拜耳/栅格混叠 | 光学 PSF 造成的高频丢失 |
| **反卷积/复原**（本管线 RL + 小波） | 已知/实测 PSF → 逆滤波；多尺度提中频 | PSF 允许范围内的对比度恢复 | 低于噪声底的频段；PSF 零点外 |
| **学习型 SR**（JSR 等） | 训练集学到"这类内容长什么样"，用先验补高频 | 观感上"细节更多"，低 SNR 也敢补 | **不保证是真信息**；错内容会换来"合理但假"的纹理 |

前两条是**线性/物理**的，能保证"多出来的东西来自数据"；第三条是**统计先验**，
强在观感、弱在可信度。三者可以叠加——JSR 实际上就是"多帧对齐 + 物理噪声模型
+ 学习型复原"。

### 9.2 JSR（`D:\Software files\superresolution`）里能看到的证据

从它自己的 `jsr_backend_manifest.json`：

- `k14_checkpoint_sha256` / `k14_best_step: 24500` / `fast_k14_weights_sha256`
  → **有训练检查点与权重**，是学习型复原网络；
- `fast_k14_network_halo: 128`、`fast_k14_gpu: WGPU` → GPU 分块推理，
  每块 128px 重叠区；
- 运行日志里的 `Transformer 恢复` → 网络结构是 **Transformer**；
- `z8_preset_source: 408 actual silent PTP captures`、`s5ii_dark_lut: 28 measured ISO`
  → 机型级**噪声/满阱/PTC 标定**（同一套物理噪声模型）；
- `fast_k14_large_motion: independent_source_windows_with_bounded_stripe_atlas`
  → 带大位移窗口的对齐。

也就是说：**它比我们多的不是"更好的叠加"，而是一张训练过的先验**，外加
更精细的传感器噪声标定。前者正是"看起来更锐"的主因——网络敢在信噪比不足的
频段补出合理结构，而物理链路到此为止。

本机实测：`jsr_backend.exe`（Stormer/K7 模式，7 帧）用 D3D12 跑会挂在
FXC 着色器编译（`forced to unroll loop`），Vulkan 可跑但 6064x4040 的 2646 个
tile 约需 17 分钟（本机核显）。所以"效果更好"是它的模型带来的，不是免费的。

### 9.3 我们这轮补上的那一半：行星摄影式多尺度锐化

物理链路里还漏了一半观感来源：**中频局部对比度**。RL 只反卷积"光学 PSF"
这一种模糊，而环形山壁、月海边界的"立体感"来自中频。行星摄影（RegiStax/
AutoStakkert）一律用多尺度小波提中频——这也是学习型超分最容易被误认为
"分辨率更高"的地方。

实现：`sr_moon.wavelet_sharpen`（à trous B3 样条 4 层，增益 0.6/1.7/1.4/1.1，
外加 0.10 的大尺度局部对比），只作用于亮度、按亮度比例回写彩色（不产生色边），
并且**从 0.89r 到 0.94r 羽化、盘缘本身不锐化**——小波在"亮盘→黑天"阶跃上
必然出现内侧亮/外侧暗的振铃，行星软件也是手动擦边的。

效果：盘内中位不变（0.488）、贴顶 0%、天空不变，环形山从"模糊团"变成
"有壁有底的环"。这一步已接进 `process_subject_roi`（`--no-subject-enhance` 可关）。

### 9.4 本机实测 JSR（2026-10-18 01:18，Stormer K7 7 帧模式）

- 调用：`jsr_backend.exe --developer-mode --raw-frame ×7 --black-level-dn 1008
  --read-noise-dn 3 --full-well-electrons 20000 --backend Vulkan`；
  D3D12 会挂在 FXC 着色器编译（`forced to unroll loop`），Vulkan 正常；
- 2646 个 tile，**1182 秒（约 20 分钟）**，输出 12128x8080（2x）DNG；
- 客观量（同一物理窗口、同一色调映射）：

| | JSR K7（7 帧） | 本管线（9 帧） |
|---|---|---|
| 盘缘 10-90% | **5.22px（原生等效）** | 2.84px |
| 天空高频噪声 | 6.7e-6 | 2.3e-5 |

JSR 的 7 帧输出**比单帧（2.97px）还软**，噪声却低 3.4 倍——这是"保守复原"
的典型特征（网络优先去噪、不轻易加细节）。注意这次喂给它的 7 帧横跨三段
重新取景（滚转 0.3°），它的对齐没能完全吃掉，也会贡献一部分软化；
它的 14 帧 K14 模式才是主力，而本组只有 9 帧凑不齐。

**结论：在"这 9 帧 + 这个视宁度"的条件下，我们的物理链在细节上不输它的
7 帧模式；它的优势在干净度和一致性，K14 才有资格谈"更好"。** 用户观感上
"JSR 更好"，很可能来自它干净的默认观感，或与我们**旧版白饼 JPG** 的对比。

### 9.5 要真正追上 JSR 还差什么

1. 训练一个自己的小模型（lunar 域、输入=本管线融合结果、目标=高清月面），
   这是唯一能补"先验"的路径；没有 GPU 训练与配对数据前不现实；
2. 或者直接调用 JSR（已支持 `--k14-backend`，但要求 14 帧；本组只有 9 帧，
   要走它的 Stormer 7 帧模式需要另接 CLI）；
3. 物理上：lucky imaging + 更大口径（见第八节）。
