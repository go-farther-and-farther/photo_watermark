## 一、super_res/sr_process.py

### 1.1 [P1] TIFF 的 EXIF 写入必定失败（piexif 不支持 TIFF）

- **问题**：原代码用 `piexif.insert()` 向 TIFF 写元数据。piexif 只支持 JPEG，对 TIFF 必抛
  `InvalidImageDataError`（实测复现），因此 README 承诺的「TIFF 带完整 EXIF」从未实现，
  只在控制台打印一行"TIFF 元数据写入失败"。
- **修复**：
  - 新增 `build_tiff_exif_tags()` 与 `_parse_rational()`，改用 `tifffile.imwrite(..., extratags=...)`
    写入 `Make(271)`、`Model(272)`、`DateTime(306)`；
  - JPG 分支继续用 piexif，保留完整 Exif 子 IFD（快门、ISO、焦距、镜头）；
  - piexif 构造改为逐字段容错（原来任何一个字段解析失败会丢掉整份 EXIF）。
- **固有限制**（已写入 README）：tifffile 不支持写 Exif 子 IFD，`Software(305)` 是其保留 tag，
  故 TIFF 只含上述三项；完整 EXIF 看 JPG。
- **验证**：extratags 写入后用 `TiffFile` 回读 271/272/306，值完全一致。

### 1.2 [P1·修复过程中新发现] 输出 TIFF 红蓝通道互换

- **问题**：保存 TIFF 前执行了 `cv2.cvtColor(img, COLOR_RGB2BGR)`。cv2 需要 BGR 是因为它自己
  编码；tifffile 只按数组顺序原样存储，文件再被按 RGB 解释时红蓝就换了。JPG 分支转 BGR 是
  正确的，TIFF 分支是错的——即此前所有 TIFF 输出颜色都是错的（JPG 预览却正常）。
- **修复**：删除 TIFF 分支的 BGR 转换，保持 RGB。
- **验证**：构造左半红、右半蓝的合成帧跑完整 `process()`，输出 TIFF 左半区
  `R=64610 > B=3648`、右半区 `B=64483 > R=3934`，通道顺序正确。

### 1.3 [P2] 去鬼影基准帧在循环内重复计算

- **问题**：`ref_cropped`/`ref_sr`（参考帧裁切 + 上采样）在融合循环内每帧重算一次，
  结果完全相同，16 帧时浪费 15 次全尺寸 resize 与大块内存分配。
- **修复**：移到循环外，只计算一次；循环结束后随 `ref_img` 一起释放。
- **验证**：端到端测试通过（见 1.2），输出尺寸与去鬼影行为不变。

### 1.4 [P3] 其他

- 两处裸 `except:` 改为 `except Exception`（避免吞掉 `KeyboardInterrupt`）；
  JPG EXIF 写入失败现在有明确提示，不再静默。

### 1.5 super_res 文档与依赖

- README：`--max-shift` 默认值 100 → 50（与 `argparse` 一致）；输出表格的 EXIF 描述改为
  与实际行为一致。
- `requirements.txt`：补充 `exifread`、`piexif`（README 安装命令里有、依赖清单里漏了）。

## 二、image_compress/image_compress.py

### 2.1 [P1] 覆盖模式写入不原子，中途失败会损坏原图

- **问题**：`keep_original=false` 时 `out_path = f`，PIL 的 `save()` 直接往原文件路径写。
  写入中途抛异常（磁盘满、权限等）会留下截断的文件，原图即损毁。
- **修复**：新增 `encode_jpeg()`（内存编码，先拿到完整字节）与 `write_atomic()`
  （写同目录 `.tmp` → `os.replace` 原子替换，失败清理临时文件）。
- **验证**：正常压缩后文件被替换、无 `.tmp` 残留；喂损坏 JPG 返回错误且原文件保留。

### 2.2 [P1] 压缩后反而变大时会删掉原图（数据丢失路径）

- **问题**：原逻辑 `saved_kb < 0` 时执行 `out_path.unlink()`。覆盖模式下 `out_path` 就是
  原图本身——先覆盖写、再发现变大、然后删除 → 唯一副本彻底消失。
- **修复**：改为在内存中编码并比较大小，`saved_kb < 0` 直接跳过、不落盘
  （`keep_original=true` 时同样不再产生多余的 `_compressed` 文件）。
- **验证**：monkeypatch `encode_jpeg` 返回更大的字节 → 返回 `None` 且原文件字节级不变。

### 2.3 [P1·测试中暴露] NEF/WIC 转换的三重缺陷

测试含单引号文件名的垃圾 NEF 时暴露：

1. **PowerShell 对 .NET 异常不改变退出码**（实测：解码失败 `returncode=0`，只有 `throw` 才
   返回 1）→ 原代码把失败当成功；
2. `OpenWrite` 在异常发生前就已创建 **0 字节输出** → 被当作成功并统计出巨大的"节省"；
3. 覆盖模式下 `OpenWrite` 直接打开目标 JPG → 转换失败时把已有 JPG 截断为 0 字节。

- **修复**：
  - PS 脚本包 `try/catch` + `$ErrorActionPreference='Stop'` + `exit 1`，异常信息经
    `[Console]::Error.WriteLine` 输出；
  - 输出先写 `.tmp` → Python 侧 `PIL.Image.verify()` 校验 → `os.replace` 原子替换；
  - 路径经新增的 `ps_quote()`（PS 单引号字符串、内部单引号翻倍）转义，文件名含 `'`
    不再破坏脚本。
- **连带修复**：`subprocess.run` 加 `errors='replace'`。中文 Windows 上 PowerShell 输出 GBK，
  原代码按 UTF-8 解码会在读线程里抛 `UnicodeDecodeError`（测试中实际崩溃）。
- **验证**：文件名含单引号的垃圾 NEF → 明确报"WIC转换失败"、无 tmp/假输出残留；
  PNG 元数据侧车 `.json` 正常生成。

### 2.4 [P2] PNG 转 JPG 丢 alpha 与 ICC 配置文件

- **问题**：`img.convert("RGB")` 会把透明通道直接丢弃（JPEG 无 alpha，透明区变黑）；
  `icc_profile` 从未传给编码器，广色域图会偏色。
- **修复**：有透明通道时先合成到白底再编码（`RGBA`/`LA`/带 transparency 的 `P` 模式）；
  PNG 与 JPG 两个分支都把 `icc_profile` 传给 `encode_jpeg()`。
- **验证**：顶部全透明的 RGBA PNG 转换后，透明区采样像素为 `(255,255,255)`。

### 2.5 image_compress/fix_audio.py [P3]

- **问题**：`pan=mono|c0=c0+c1` 双声道直接相加，振幅翻倍、易削顶。
- **修复**：`pan=mono|c0=0.5*c0+0.5*c1`。

## 三、根目录照片整理脚本

### 3.1 [P2] move_by_date.py 只扫年份目录顶层

- **问题**：匹配年份照片用 `year_path.iterdir()`，年份文件夹一旦有子目录，其中的照片全部
  漏掉；而 `find_duplicates.py` 用 `rglob`，两个脚本对同一批文件的可见范围不一致。
- **修复**：改用 `year_path.rglob("*")`；`has_sub_images` 更名 `has_top_files`（原名与实际
  含义相反）。

### 3.2 [P2] organize_by_year.py / organize_by_half_year.py 无确认直接移动

- **问题**：一运行就把源目录文件 move 走，没有任何确认，与仓库其他脚本（`find_hash_dupes`、
  `move_by_date` 均有 y/n 关卡）风格不一致，误操作成本高。
- **修复**：运行时先打印源/输出目录，要求输入 `y` 确认，否则退出。

### 3.3 [P3] rename_by_date.py 重复运行会叠加前缀

- **问题**：再跑一次会把 `20240115-DSC_0367.JPG` 变成 `20240115-20240115-DSC_0367.JPG`
  （`exists` 检查挡不住，因为叠加后的名字是新名字）。
- **修复**：新增 `ALREADY_PREFIXED` 正则，文件名已带 8 位日期前缀或 `无日期-` 前缀时跳过
  并计数，重复运行安全（幂等）。

### 3.4 [P3] find_hash_dupes.py 排除目录只查直接父目录

- **问题**：`f.parent.name not in EXCLUDE_FOLDERS` 只看直接父目录，`test\sub\a.jpg` 这类
  深层文件不会被排除。
- **修复**：改为 `set(f.parts) & set(EXCLUDE_FOLDERS)`，路径任意层级命中即排除
  （原 `"重复" not in f.parts` 的特判并入其中）。
